# E13-18 - ROMs de timing et d'interruptions: decouvrir et documenter
Epopee: E13 | Type: doc | Dependances: E13-17 | Taille estimee: ~0 lignes

## Contexte
Des ROMs de test de timing (Woodmass, Raxoft, et autres: contention, floating bus, interruptions, HALT) completent les suites precedentes. La liste exacte n'est pas dans ce depot.

## Lire d'abord
- `docs/qa/DECISIONS.md` et `docs/qa/FAQ_Z80.md` (a consulter avant toute question)

## Write only in
- `docs/specs/36_TIMING_ROMS.md`
- `tests/manifest.toml`
- `docs/qa/FAQ_Z80.md`
- `docs/qa/inbox/**` (questions uniquement)

## Specification
Recherche les ROMs de timing/interruptions du Z80 disponibles publiquement (Woodmass `Z80 timing/contention test`, Raxoft `z80test`/`intr`/`halt`, jsmoo...) : pour chacune note l'URL reelle, la licence, le format, comment elle rapporte son resultat (ecran, bordure, code), la machine exigee. Ecris `docs/specs/36_TIMING_ROMS.md` avec un tableau et, pour chaque ROM retenue, le critere de reussite. Ajoute les fichiers retenus a `tests/manifest.toml` (url, sha256). N'invente aucune ROM : si une source est inaccessible, pose une question Q&R et note-la `UNAVAILABLE`.


### Notes
Tout ce qui est marque `UNKNOWN - to confirm` DOIT etre verifie sur la source reelle (git clone --depth 1 / curl) puis documente dans le fichier indique; si la source est inaccessible depuis le reseau de la machine: question Q&R (docs/02_QA_PROTOCOL.md), ne rien inventer.
