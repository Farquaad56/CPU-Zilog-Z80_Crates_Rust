## Specification
Dans `bus.rs` (`pub mod bus;`, re-exports `Bus`, `Cycle`, `SimpleRam`): le trait EXACT de l'architecture (read, write, io_read, io_write, int_ack, extra_wait, irq, nmi, busrq, on_tick) avec les valeurs par defaut de la doc, `pub enum Cycle { Fetch, MemRead, MemWrite, IoRead, IoWrite, IntAck, Internal }` (derive Clone Copy Debug PartialEq Eq),
et `pub struct SimpleRam { pub mem: [u8; 65536] }` implementant `Bus` (lit/ecrit `mem`, `io_read` renvoie 0xFF). `SimpleRam::new()` toute la memoire a 0.
Attention taille: `[u8; 65536]` sur la pile est acceptable (64 Ko) mais fournis `SimpleRam::boxed()` seulement sous `#[cfg(feature = "std")]`.

## 4. API publique (resume)

```rust
pub struct Pins(pub u64);
pub struct Cpu { pub regs: Regs, /* moteur prive */ }
pub trait Bus {
    fn read(&mut self, addr: u16) -> u8;
    fn write(&mut self, addr: u16, data: u8);
    fn io_read(&mut self, _port: u16) -> u8 { 0xFF }
    fn io_write(&mut self, _port: u16, _data: u8) {}
    fn int_ack(&mut self) -> u8 { 0xFF }                  // octet place sur le bus pendant l'acquittement INT
    fn extra_wait(&mut self, _kind: Cycle, _addr: u16) -> u8 { 0 }   // T-states d'attente (contention ZX, WAIT arcade)
    fn irq(&mut self) -> bool { false }  fn nmi(&mut self) -> bool { false }  fn busrq(&mut self) -> bool { false }
    fn on_tick(&mut self, _pins: Pins) {}                 // appele a CHAQUE T-state (horloge des peripheriques)
}
pub enum Cycle { Fetch, MemRead, MemWrite, IoRead, IoWrite, IntAck, Internal }
impl Cpu { pub fn new() -> Cpu; pub fn reset(&mut self); pub fn tick(&mut self, pins: Pins) -> Pins;
           pub fn step<B: Bus>(&mut self, bus: &mut B) -> u32; pub fn at_instruction_boundary(&self) -> bool; }
```

`step()` est implemente au-dessus de `tick()` (une seule logique): il boucle `tick`, sert la memoire/ports via `Bus` selon les broches, insere `extra_wait`, et s'arrete a la frontiere d'instruction. Le CPU n'a donc qu'UNE implementation de timing.

# 32 - REUTILISATION DANS D'AUTRES EMULATEURS (consoles et bornes d'arcade)

Cibles typiques: ZX Spectrum / MSX / ColecoVision / SG-1000 / Master System / Game Gear (IM1, E/S), Mega Drive (Z80 son avec BUSRQ/BUSAK et RESET),
Neo Geo (Z80 son), bornes (Pac-Man: IM2 avec vecteur ecrit par OUT; Galaga: 3 Z80; Capcom, Konami, Taito: peripheriques Z80 CTC/PIO/SIO en daisy chain).

Exigences deduites:
1. `no_std`, sans alloc, sans unsafe, aucune dependance => utilisable en WASM, microcontroleur, ou projet existant.
2. Pas d'horloge interne: l'hote appelle `tick()` ou `step()`; le diviseur d'horloge (par ex. Z80 a 3,579545 MHz) est a la charge de l'hote.
3. `Bus::extra_wait` pour la contention memoire (ZX Spectrum) et les WAIT d'arcade; `on_tick` pour cadencer VDP/son/CTC au T-state.
4. `Bus::int_ack` + `irq()` pour les modes IM0/IM1/IM2 et les vecteurs places par un peripherique.
5. `busrq()` pour les systemes a bus partage (Mega Drive); `Pins::BUSAK` expose l'etat.
6. `RETI` observable (daisy chain Z80 CTC/PIO/SIO).
7. Plusieurs CPU dans un meme programme (arcade): aucun etat global ni statique mutable.
8. Etat complet lisible (`cpu.regs`) pour debuggers et sauvegardes d'etat (serialisation hors crate en v1).

Exemples fournis par E16: machine CP/M minimale, machine ZX-like avec contention, machine a bus partage (BUSRQ), machine IM2 avec CTC factice.
