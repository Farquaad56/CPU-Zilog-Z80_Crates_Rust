# E13-12 - FUSE: decouvrir et documenter le format
Epopee: E13 | Type: doc | Dependances: E13-11 | Taille estimee: ~0 lignes

## Contexte
Les tests FUSE (`z80/tests/tests.in` et `tests.expected`) donnent, par opcode, un etat initial et l'etat final + les evenements de bus horodates (MR MW PR PW MC PC).

## Lire d'abord
- `docs/qa/DECISIONS.md` et `docs/qa/FAQ_Z80.md` (a consulter avant toute question)

## Write only in
- `docs/specs/34_FUSE_FORMAT.md`
- `docs/specs/30_TEST_SUITES.md`
- `docs/qa/FAQ_Z80.md`
- `docs/qa/inbox/**` (questions uniquement)

## Specification
Trouve la source exacte (depot fuse-emulator ou miroir) et recupere `tests.in` et `tests.expected` dans `tests/roms/fuse/`. Ecris `docs/specs/34_FUSE_FORMAT.md` : structure d'un enregistrement de `tests.in` (nom, registres sur 2 lignes, I R IFF1 IFF2 IM halted tstates, memoire `addr bytes -1`), de `tests.expected` (evenements `tstate type addr data`, etat final, memoire modifiee), signification de chaque code d'evenement, regle de comparaison (nombre de T-states de l'instruction, ordre des evenements), cas particuliers. Mets a jour la ligne FUSE du tableau de `docs/specs/30_TEST_SUITES.md` (URL reelle). Pas de code Rust.
