# E03-12 - Cpu::step: instruction complete via tick

## Specification
`pub fn step<B: Bus>(&mut self, bus: &mut B) -> u32`: execute jusqu'a la prochaine frontiere d'instruction, renvoie le nombre de T-states (attente incluse).
Boucle: `pins_in` = precedent `pins_out` avec: si `MREQ|RD` -> `data = bus.read(addr)` (a fournir AU TICK SUIVANT dans `pins_in`: le CPU latche au T3); si `IORQ|RD` et pas `M1` -> `bus.io_read(addr)`; si `MREQ|WR` -> `bus.write(addr, data)` (une seule fois par cycle: au tick ou WR apparait); idem `IORQ|WR` -> `bus.io_write`.
`wait = bus.extra_wait(cycle_kind, addr)`: au 1er tick d'un cycle (A valide, t0) demande les T d'attente et maintient `Pins::WAIT` pendant ce nombre de ticks au moment de l'echantillonnage. Appelle `bus.on_tick(pins_out)` a chaque tick. `irq()/nmi()/busrq()` du Bus sont traduits en broches INT/NMI/BUSRQ dans `pins_in` (traitement par E09; ici seulement la transmission).
Garde contre boucle infinie: `debug_assert!` si plus de 100 ticks sans frontiere.

## 4. API publique (resume)

```rust
pub struct Pins(pub u64);
pub struct Cpu { pub regs: Regs, /* moteur prive */ }
pub trait Bus {
    fn read(&mut self, addr: u16) -> u8;
    fn write(&mut self, addr: u16, data: u8);
    fn io_read(&mut self, _port: u16) -> u8 { 0xFF }
    fn io_write(&mut self, _port: u16, _data: u8) {}
    fn int_ack(&mut self) -> u8 { 0xFF }                  // octet place sur le bus pendant l'acquittement INT
    fn extra_wait(&mut self, _kind: Cycle, _addr: u16) -> u8 { 0 }   // T-states d'attente (contention ZX, WAIT arcade)
    fn irq(&mut self) -> bool { false }  fn nmi(&mut self) -> bool { false }  fn busrq(&mut self) -> bool { false }
    fn on_tick(&mut self, _pins: Pins) {}                 // appele a CHAQUE T-state (horloge des peripheriques)
}
pub enum Cycle { Fetch, MemRead, MemWrite, IoRead, IoWrite, IntAck, Internal }
impl Cpu { pub fn new() -> Cpu; pub fn reset(&mut self); pub fn tick(&mut self, pins: Pins) -> Pins;
           pub fn step<B: Bus>(&mut self, bus: &mut B) -> u32; pub fn at_instruction_boundary(&self) -> bool; }
```

`step()` est implemente au-dessus de `tick()` (une seule logique): il boucle `tick`, sert la memoire/ports via `Bus` selon les broches, insere `extra_wait`, et s'arrete a la frontiere d'instruction. Le CPU n'a donc qu'UNE implementation de timing.

## 2. API

```rust
impl Cpu {
    pub fn new() -> Cpu;
    pub fn reset(&mut self);                     // etat apres RESET (voir 23_UNDOCUMENTED.md)
    pub fn tick(&mut self, pins: Pins) -> Pins;  // 1 appel = 1 T-state (une periode d'horloge)
    pub fn at_instruction_boundary(&self) -> bool;
    pub fn step<B: Bus>(&mut self, bus: &mut B) -> u32; // execute jusqu'a la prochaine frontiere, renvoie les T-states
}
```

Contrat de `tick(pins_in) -> pins_out`:
- `pins_in` contient les ENTREES vues par le CPU pendant ce T-state: D0..D7 (donnee fournie par l'hote), WAIT, INT, NMI, BUSRQ, RESET.
- `pins_out` = etat des SORTIES apres ce T-state (A, M1, MREQ, IORQ, RD, WR, HALT, RFSH, BUSAK) + D0..D7 quand le CPU ecrit.
- L'hote lit `pins_out`: si `MREQ|RD` -> il place la donnee de la memoire dans D0..D7 de `pins_in` du tick SUIVANT; si `MREQ|WR` -> il memorise D0..D7 a l'adresse A; si `IORQ|RD` / `IORQ|WR` idem pour les ports.

## Tests
Tous les tests sont prefixes par `e03_12_`.

- `e03_12_step_nop` : RAM [00]: step renvoie 4
- `e03_12_step_ld_bc_nn` : [01 34 12]: 10 T, memoire lue aux bonnes adresses (bus espion enregistre les lectures: 0,1,2)
- `e03_12_step_write_logged` : [DD 36 05 77] avec un bus espion: exactement 1 appel write(IX+5, tmp_l) (la semantique est absente donc tmp_l vaut 0x77 car lu par R5 dans TMP.L)
- `e03_12_extra_wait_adds` : un bus avec extra_wait=2 sur Fetch: NOP dure 6
- `e03_12_on_tick_count` : on_tick appele autant de fois que de T-states (4 pour NOP)
- `e03_12_io_read_called` : [DB 10] appelle io_read une fois
- `e03_12_returns_tstates` : step renvoie la somme T + attente
