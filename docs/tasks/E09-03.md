# E09-03 - Cadre d'acceptation des interruptions
Epopee: E09 | Type: code | Dependances: E09-02 | Taille estimee: ~130 lignes

## Contexte
Mecanisme commun NMI/INT : echantillonnage a la frontiere d'instruction, EI retarde, pas d'acceptation entre un prefixe et son opcode. Les sequences elles-memes sont en E09-04..06.

## Specification
Ajoute aux champs d'`Engine` : `irq: IrqKind` (enum `None, Nmi, Int`), `nmi_latch: bool`, `nmi_prev: bool`, `int_level: bool`.
- A chaque `tick` : `int_level = pins.has(INT)` (niveau) ; `if pins.has(NMI) && !nmi_prev { nmi_latch = true }; nmi_prev = pins.has(NMI)` (front montant).
- Au debut d'une instruction (`!active`), AVANT le fetch normal : `if nmi_latch { nmi_latch=false; start_nmi() } else if int_level && regs.iff1 && !eng.ei_delay { start_int() } `. (start_* = stubs ici qui ne font rien, remplis par les taches suivantes.) 
- `ei_delay` : positionne par le hook EI (E05-03) pour la prochaine frontiere ; a la frontiere de l'instruction SUIVANT EI il est remis a false APRES le test (donc INT est ignore une fois). `EI` suivi de `EI` reste inhibe.
- Jamais d'acceptation au milieu d'une chaine de prefixes (DD/FD/ED/CB) : l'etat `active` reste vrai entre le prefixe et l'opcode, donc le test n'a pas lieu ; verifie-le par un test.
- `ei_delay` existe deja (E05-03). `reset()` remet aussi `irq=None`, `nmi_latch=false`, `nmi_prev=false`.
- `Cpu::set_irq_line` n'existe pas : tout passe par `tick(pins)` / `Bus::irq()`.

## 1. Echantillonnage

- NMI: detection sur front montant (memorisee), prise en compte a la fin de l'instruction en cours (pas apres un prefixe DD/FD/ED/CB seul).
- INT: niveau, echantillonne a la fin de l'instruction; ignore si `IFF1 = 0` ou si l'instruction qui vient de finir est `EI` (l'interruption est inhibee pendant l'instruction suivant `EI`; `EI` suivi de `EI` reste inhibe).
- Pas d'acceptation entre un prefixe (DD, FD, ED, CB) et son opcode.
<!-- end -->

<!-- begin docs/specs/22_INTERRUPTS.md#4. EI -->
## 4. EI / DI / LD A,I

- `EI`: IFF1=IFF2=1, mais l'acceptation d'INT est retardee d'une instruction.
- `LD A,I` / `LD A,R`: P/V = IFF2. (U) NMOS: si une INT est acceptee juste apres cette instruction, P/V est remis a 0 (bug NMOS documente).
<!-- end -->

## Tests
Tous les tests sont prefixes par `e09_03_`.

- `e09_03_nmi_edge_latched` : NMI actif 3 ticks de suite = UNE seule demande
- `e09_03_nmi_second_edge` : retombee puis remontee = nouvelle demande
- `e09_03_int_level_ignored_when_di` : INT actif avec IFF1=0: aucun start_int
- `e09_03_ei_delay_one_instruction` : EI puis NOP avec INT actif: l'interruption n'est vue qu'apres le NOP
- `e09_03_ei_ei` : EI EI NOP : toujours inhibe pendant EI EI
- `e09_03_no_int_mid_prefix` : DD (prefixe) puis opcode: INT ignore entre les deux
